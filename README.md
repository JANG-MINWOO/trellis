# Trellis

Claude Code 옆자리에서, AI가 코드를 짜는 동안 무엇을 왜 바꿨는지 사람이 계속 이해하고 책임질 수 있게 잡아 주는 데스크톱 앱입니다.

*Keep the intent of your project understood while you work with AI agents.* [English README](README.en.md)

터미널에서 Claude Code와 대화하는 경험은 그대로 두고, 그 옆에 이번 작업의 의도, 턴별 타임라인, 영역별로 묶인 변경, 결정 기록, 구조 건강을 보여 줍니다. 식물이 격자(trellis)를 타고 자라듯, 구조를 잡아 주면서 사람과 프로젝트가 같이 자라게 하자는 뜻으로 지은 이름입니다.

## 왜 만들었나

AI에게 일을 맡기면 결과물은 빨리 나오지만 이해는 따라오지 않습니다. "그 문제 어떻게 해결했어?"라는 질문에 "클로드가 그러던데요"만 남고, 결정의 이유는 대화창에 묻히고, AI 변경이 쌓이면서 구조도 조금씩 무너집니다.

그렇다고 사람이 diff를 한 줄씩 다시 읽는 방식은 오래 가지 못합니다. Trellis는 둘을 나눕니다. 코드가 맞는지 확인하는 일은 테스트와 자동 검사와 AI에 맡기고, 사람은 무엇을 왜 만들지 정하고 책임지는 일, 즉 의도와 결정에 집중합니다. 사람이 쓰는 시간은 변경량이 아니라 결정 개수에 비례해야 한다는 것이 출발점입니다.

판단 근거는 [docs/BACKGROUND.md](docs/BACKGROUND.md)에 자세히 있습니다.

## 지금 되는 것 (M1~M4)

- 프로젝트 목록: 폴더를 추가하고 Obsidian 볼트처럼 오갑니다. 다른 프로젝트로 옮겨도 터미널 세션은 유지됩니다.
- 내장 터미널: 프로젝트를 열면 실행 카드에서 권한 방식(Claude 설정 따르기, 매번 확인, 수정 자동 허용, 자동 판단, 계획만, 모든 확인 건너뛰기)을 고르고 지난 대화를 이어서 하거나 새 대화를 시작합니다. 한 프로젝트에서 Claude 대화와 셸을 여러 탭으로 열 수 있습니다. 탭을 멈추면 그 자리에서 다시 시작할 수 있습니다.
- 입력창과 이미지: Claude 탭 아래 입력창에서 한글을 완성해 보내고(언어 전환 직후 자모 분리 버그 우회), 클립보드 이미지를 붙여넣으면 Claude 입력칸에 `[Image #N]`으로 첨부됩니다. 터미널에 Cmd+V로 붙여넣어도 같고, 파일은 끌어다 놓으면 경로가 들어갑니다.
- 작업 의도: 하려는 것, 하면 안 되는 것, 바뀔 것 같은 곳(영역)을 적어 두고 Claude 입력창에 붙여 넣습니다. 턴이 끝나면 예상한 곳과 실제로 바뀐 곳을 비교해 "예상 밖 변경"을 보여 주고, 하면 안 되는 것은 동작 명세의 불변식으로 옮길 수 있습니다.
- 타임라인: 프롬프트 하나에서 도구 사용, 종료까지를 턴 카드 하나로 보여 주고, 승인을 기다리는 중이면 표시합니다. 턴에서 바뀐 파일은 턴 시작과 끝의 git 스냅샷으로 계산해서, Claude가 Bash로 고친 파일도 빠지지 않습니다. 탭이 여럿이면 탭별로 걸러 볼 수 있습니다.
- 변경: 이번 실행을 시작한 시점(또는 마지막 커밋) 이후 바뀐 파일을 영역별로 묶어 줄 수와 함께 보여 주고, 쓰는 편집기로 엽니다.
- 결정: Claude가 턴을 마치면 변경을 분석해 되돌리기 어렵거나 앞으로의 작업을 좌우할 결정(의존성, 데이터 형식, 인증, 구조 등)을 카드로 올립니다. 카드는 "그래서 무엇이 달라지나"를 먼저 보여 주고, 이유는 사람이 직접 씁니다(AI의 추측은 접혀 있는 참고일 뿐). 기록하면 결정 폴더(기본 `docs/decisions/`)에 번호를 이어 문서로 남습니다. 인증·결제·마이그레이션 같은 확인 필요 영역이 바뀌면 분석과 상관없이 카드가 뜹니다.
- 동작: 같은 분석에서 사용자에게 보이는 동작이 바뀐 것을 찾아, 사람이 문장을 고쳐 반영하면 영역별 명세(`docs/specs/`, EARS 문장과 `B-001` 같은 고정 번호)에 들어갑니다. 테스트에 번호를 적으면 연결된 테스트 수가 보입니다.
- 건강: 구조 규칙(긴 파일, 파일이 몰린 폴더, 중복 코드, 순환 의존, 경로 경계)의 위반, 지난주보다 나빠진 곳, 문서가 가리키는데 없는 경로, 큰 파일과 밀집 폴더를 보여 줍니다. 지금 있는 위반은 기준선으로 얼려 두고 새로 생긴 것만 볼 수 있고, 규칙 파일과 지침·결정·명세 문서의 뼈대를 만들어 주는 시작 템플릿이 있습니다.
- 작업 끝 검사(선택): 켜 두면 Claude가 작업을 마칠 때 이번 턴이 새로 만든 규칙 위반과 프로젝트의 검사 명령(예: `npm test`)을 확인하고, 문제가 있으면 Claude에게 이유와 함께 되돌려 보내 고치게 합니다(한 턴에 한 번).
- 편집기: 파일을 처음 열 때 이 컴퓨터에서 찾은 편집기(VS Code, Cursor, Zed, Sublime, IntelliJ 계열 등) 중에서 한 번 고릅니다. 기본 앱으로 열기, Finder/탐색기에서 보기도 고를 수 있습니다.
- 설정: 한국어/영어, 다크/라이트 테마, claude 경로와 추가 인자, 권한 기본값, 분석 모델, 프로젝트를 열 때 묻기/바로 시작, 편집기, 터미널 GPU 렌더링, 프로젝트별 결정·명세 폴더, 기록 언어, 작업 분석 켜기/끄기, 확인 필요 영역, 작업 끝 검사와 검사 명령.

Trellis는 IDE가 아닙니다. 파일 내용이나 diff는 직접 보여 주지 않고 편집기로 엽니다.

## 앞으로 할 것

M2~M4를 구현했고, 0.2.0을 실제 프로젝트에서 써 보며 버그를 잡는 단계입니다. 순서와 완료 기준은 [docs/PLAN.md](docs/PLAN.md) §8에 있습니다.

- M5 v1 마감: 큰 저장소 성능(규칙 분석을 작업 스레드로, 이벤트 기록 회전), 코드 서명, 자동 업데이트, Windows 실기 확인.

## 어떻게 동작하나

- 이벤트: Trellis가 claude를 실행할 때 `--settings`로 HTTP 훅을 붙입니다. 훅은 `127.0.0.1`에서 토큰으로 보호되는 Trellis 서버로 이벤트를 보냅니다. Trellis가 응답하지 않아도 Claude는 멈추지 않습니다. 작업 끝 검사를 켠 경우에만 Stop 훅의 답을 검사가 끝날 때까지(최대 약 2분) 미룹니다. 대상 저장소의 `.claude` 설정은 건드리지 않고, 거기 있던 훅과 함께 돕니다. (ADR-0003, 0027)
- 변경: 훅이 아니라 git으로 계산합니다. Claude가 Bash로 만든 파일도 잡힙니다. 기준점은 임시 인덱스로 찍는 스냅샷이라 작업 트리, 인덱스, 브랜치를 건드리지 않습니다. (ADR-0014)
- 분석: 턴이 끝나면 `claude -p`를 도구 없이, 사용자 설정의 훅과 MCP를 끈 채(`--restricted --strict-mcp-config`) 임시 폴더에서 한 번 실행해 결정과 동작 변경 후보를 JSON으로 받습니다. (ADR-0023)
- 규칙: 대상 저장소의 `.trellis/rules.json`과 `.trellis/baseline.json`을 git 트리에서 읽어 검사합니다. 턴은 턴 시작 시점의 규칙으로 판단해, 에이전트가 규칙을 느슨하게 고쳐 통과할 수 없습니다. (ADR-0026, 0027)
- 터미널 화면을 파싱하지 않습니다. Claude Code 업데이트로 바뀔 수 있는 부분(훅 입력 필드, 응답 형식, CLI 플래그)은 `src/main/features/agents/claude-code/` 한 곳에 모았고, 다른 곳에서 쓰면 린트가 막습니다. (ADR-0009)

## 데이터와 개인정보

- 설정, 프로젝트 목록, 이벤트 기록(프롬프트와 명령 포함), 오류 로그(`logs/main.log`)는 앱 데이터 폴더에만 저장하고 외부로 보내지 않습니다. macOS는 `~/Library/Application Support/Trellis`, Windows는 `%APPDATA%\Trellis`이고, 개발 빌드는 `Trellis-dev`를 따로 씁니다. 설정이나 프로젝트 목록 파일이 깨져 읽을 수 없으면 덮어쓰지 않고 `.corrupt-<시각>`으로 옮겨 둡니다.
- 대상 저장소의 파일은 고치지 않습니다. 변경 스냅샷 때문에 `.git/objects`에 참조 없는 객체가 남을 수 있는데, 이는 `git gc`가 정리합니다. git이 아닌 폴더에서 "git 시작하기"를 누르면 그때만 `git init`을 실행합니다.
- 대상 저장소에는 사람이 버튼을 눌러 승인한 것만 씁니다: 결정 기록, 동작 명세, `.trellis/` 규칙·기준선, 시작 템플릿 파일. 덮어쓰지 않습니다.
- 작업 분석을 켜 두면 턴마다 그 턴의 diff 일부(최대 약 4만 자)와 요청, 의도가 로그인한 Claude Code를 통해 Anthropic으로 한 번 더 전송됩니다. Claude 세션 자체가 보내는 것과 같은 경로이고, 프로젝트 설정에서 끌 수 있습니다.

## 상태와 알려진 한계

버전 0.2.0. M1(셀프 호스팅)과 M2~M4(결정 감지, 구조 규칙과 작업 끝 검사, 동작 명세와 예측 비교)를 구현했고, 실제 프로젝트에서 써 보며 버그를 잡는 중입니다.

- 코드 서명 전이라 처음 실행할 때 보안 경고가 뜹니다.
- Windows 설치 파일은 CI에서 만들지만 실제 Windows PC에서는 아직 확인하지 않았습니다(키 처리, ConPTY 등).
- 지원하는 에이전트는 Claude Code뿐이고, 2.1.29x에서 확인했습니다.
- 셸 탭에서 직접 실행한 `claude`에는 이벤트 브리지가 붙지 않아 타임라인에 나오지 않습니다. Claude 탭을 쓰세요.
- Claude 안에서 `/clear`나 대화 압축으로 새로 시작한 세션은 타임라인에 "대화 시작"으로 남지 않습니다(턴은 그대로 기록됩니다).
- 같은 폴더에서 Claude 탭 여러 개가 동시에 파일을 고치면, 턴별 변경에 다른 탭의 변경이 섞일 수 있습니다.
- macOS 설치 파일은 Apple Silicon(arm64)용만 만듭니다.
- 작업 분석은 변경이 있는 턴마다 Claude 호출이 한 번 더 들어갑니다(sonnet 기준 약 8초, 구독 사용량). 분석이 결정을 빠뜨리거나 결정이 아닌 것을 올릴 수 있습니다.
- 규칙 분석은 메인 프로세스에서 돕니다. 파일 7천 개 정도에서 갱신 한 번에 약 0.7초가 걸리고, 더 큰 저장소는 아직 최적화하지 않았습니다.
- import 추출은 정규식 기반이라 동적 import나 특이한 별칭은 놓칠 수 있습니다(놓친 import는 규칙 판단에서 빠질 뿐 오탐을 만들지는 않습니다).

## 설치

아직 릴리스 태그가 없어서, GitHub Actions가 만든 설치 파일을 저장소 Actions 탭의 artifacts에서 받습니다. `v*` 태그를 달면 Releases에도 올라갑니다.

- macOS: `Trellis-<버전>-mac-arm64.dmg`. 서명 전이라 처음에는 Finder에서 앱을 우클릭 → 열기로 실행합니다.
- Windows: `Trellis-Setup-<버전>-win-x64.exe`. SmartScreen이 뜨면 "추가 정보 → 실행"을 누릅니다.

필요한 것: 로그인된 [Claude Code](https://code.claude.com/docs), git. 별도 API 키는 필요 없습니다. macOS에서 Finder로 실행해도 로그인 셸의 PATH를 읽어 claude와 git을 찾습니다.

## 개발

Node 24와 npm 11을 씁니다(CI와 같은 버전).

```bash
npm install          # 의존성 설치, node-pty 실행 권한 복구, 네이티브 모듈 준비
npm run dev          # 개발 빌드. 저장하면 화면은 바로 바뀌고 main은 다시 시작 (데이터 폴더 Trellis-dev)
npm run install:local  # 지금 코드로 /Applications/Trellis.app 교체 (dmg 없이, 실행 중이면 종료할 때 교체)
npm run check        # 타입·린트·포맷·i18n·구조 규칙·단위 테스트 (커밋 전 필수)
npm run e2e          # 빌드 후 가짜 claude로 e2e (실행·탭, 의도→결정·명세, 작업 끝 검사)
npm run dist:mac     # macOS 설치 파일 (Windows 설치 파일은 Windows에서 dist:win)
```

아래 두 테스트는 직접 켜야 돌고, `out/`의 빌드를 쓰므로 먼저 `npm run build`를 합니다. 둘 다 임시 데이터 폴더를 씁니다.

```bash
TRELLIS_REAL_CLAUDE=1 npx playwright test real-claude   # 실제 claude로 전 구간 확인 (구독 사용량 소모)
TRELLIS_BROWSE_PATH=<폴더> npx playwright test browse   # 기존 폴더를 Claude 없이 열어 패널 스크린샷
```

Trellis로 Trellis를 개발할 때는 패키지된 안정 빌드에서 Claude를 실행하고, 그 안에서 `npm run dev`로 개발 빌드를 띄웁니다. 고치는 중인 앱으로 그 앱을 고치지 않기 위해서입니다(ADR-0011). 개발 빌드로 충분히 써 보고 만족하면 `npm run install:local`로 안정 빌드를 교체합니다. 설치 파일(dmg·exe)은 남에게 줄 버전을 찍을 때만 만듭니다(ADR-0021). 지금 실행 중인 빌드는 상태 바 오른쪽(예: `0.2.0+14ecc50`)에서 확인합니다.

코드 구조와 작업 규칙은 [AGENTS.md](AGENTS.md)에 있습니다. 사람과 에이전트(Claude Code, Codex 등)가 같이 따르는 규칙이고, `CLAUDE.md`는 이 파일의 심볼릭 링크입니다.
