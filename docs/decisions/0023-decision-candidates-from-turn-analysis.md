# ADR-0023: 결정은 턴 분석으로 찾고, 이유는 사람이 쓴다

- 상태: 채택
- 날짜: 2026-10-10
- 결정한 사람: 에이전트 제안 (PLAN M2) → 미누 진행 승인

## 결정
Claude가 턴을 마치고(Stop) 파일이 바뀌었으면, 그 턴의 diff·요청·마지막 메시지·의도를 넣어 격리된 헤드리스 호출을 한 번 한다(`-p --restricted --strict-mcp-config --tools "" --no-session-persistence --json-schema`, 작업 폴더는 임시 폴더). 결정 후보(최대 3개)와 동작 변경 후보(최대 5개, ADR-0024)를 한 번에 받는다. 후보는 이벤트 원장에만 쌓이고, 사람이 이유를 직접 적어 "기록하기"를 눌러야 결정 폴더에 `NNNN-제목.md`로 쓰인다. AI가 추측한 이유는 접힌 곳에 "추측"으로만 보이고, 그대로 쓰려면 따로 눌러야 하며 기록 파일에 "AI 추측"이라고 남는다. 확인 필요 영역(인증·결제·마이그레이션 등 glob, 프로젝트별 설정)이 바뀌면 분석과 상관없이 확인 카드를 만든다.

## 이유
"클로드가 그러던데요"를 막으려면 이유가 사람 머리에서 나와야 한다. AI가 이유까지 채우면 사람은 읽지 않고 승인한다. 결과와 대가는 비개발자도 판단할 수 있으므로 카드 맨 앞에 둔다(ADR-0012). `--restricted`는 사용자·프로젝트 설정의 훅을 끄면서 구독 로그인은 유지한다(`--bare`는 로그인까지 끈다). 실제 확인: 훅이 돌지 않았고 `structured_output`이 왔다.

## 대안
- 결정과 동작을 따로 호출: 사용량이 두 배다.
- 훅 이벤트(도구 이름)로만 규칙 기반 감지: 의존성 추가 정도만 잡고, 구조·데이터 결정은 못 잡는다.
- 후보를 바로 파일로 쓰기: 대상 저장소에 사람이 승인하지 않은 문서가 쌓인다(원칙 위반).

## 결과와 대가
변경이 있는 턴마다 Claude 호출이 한 번 더 든다(설정에서 프로젝트별로 끔, 모델 선택, 사용 횟수 표시). 분석은 몇 초~수십 초 걸리므로 백그라운드로 돌고, 그동안 "살펴보는 중"이 보인다. 분석이 틀리거나 빠뜨릴 수 있다 — 후보는 제안일 뿐이고 "결정 아님"으로 버린다. 이미 기록됐거나 대기·기각된 제목은 다시 묻지 않는다.
