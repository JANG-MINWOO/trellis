# ADR-0014: 변경은 git 임시 인덱스 스냅샷으로 계산한다

- 상태: 채택
- 날짜: 2026-10-09
- 결정한 사람: 에이전트 (구현 결정) → 미누 확인(2026-10-10)

## 결정
"이번 실행 이후" 변경은 Claude를 띄우기 직전에 작업 트리 전체(추적 + 추적 안 된 파일, .gitignore 준수)를 tree 객체로 찍어 두고, 지금 상태의 tree와 `git diff-tree`로 비교해 계산한다. tree는 실제 인덱스를 복사한 임시 인덱스(`GIT_INDEX_FILE`)에 `git add -A` 후 `git write-tree`로 만든다. "마지막 커밋 이후"는 `HEAD^{tree}`와 비교한다. 훅 이벤트는 "어느 턴이 어느 파일을 건드렸나"에만 쓴다.

## 이유
- Claude는 Write 도구가 아니라 Bash로도 파일을 만든다(실측: haiku가 Bash로 파일 생성). 훅만으로는 변경을 놓친다.
- `git stash create`는 추적 안 된 파일을 담지 못한다.
- 작업 트리, 실제 인덱스, refs를 건드리지 않는다(대상 저장소 무수정 원칙). 실제 인덱스를 복사해 쓰면 git의 stat 캐시 덕에 바뀌지 않은 파일은 다시 해시하지 않는다.

## 대안
- 훅 이벤트의 파일 경로만 모으기: Bash 변경을 놓친다.
- 파일 감시로 직접 diff: git이 이미 잘하는 일을 다시 만든다.

## 결과와 대가
- `.git/objects`에 참조 없는 객체가 남는다(git gc가 정리). 20MB 넘는 추적 안 된 파일은 스냅샷에서 뺀다.
- Git LFS 저장소에서는 `git add`가 clean 필터를 돌린다 — 문제가 보이면 다시 검토한다.
- 기준점은 Claude를 띄우기 전에 잡는다(최대 4초 기다림). 늦게 잡으면 초기 변경이 기준점에 묻힌다(실제로 테스트에서 재현됨).

## 덧붙임 (2026-10-09)
임시 인덱스를 복사하면 인덱스 파일의 수정 시각이 "지금"이 되어 git의 racy-git 검사(인덱스와 같은 초에 쓰인 항목은 내용을 다시 확인)가 꺼진다. 그 결과 커밋 직후 같은 초에 같은 크기로 바뀐 파일을 놓쳤다(CI에서 25번 중 1번꼴로 재현). 복사본에 원래 인덱스의 수정 시각(초 단위 내림)을 그대로 준다. 수정 후 140번 연속 통과.
