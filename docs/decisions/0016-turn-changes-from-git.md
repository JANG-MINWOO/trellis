# ADR-0016: 턴별 변경도 git 스냅샷으로 계산한다

- 상태: 채택
- 날짜: 2026-10-09
- 결정한 사람: 에이전트 (미누 피드백: 타임라인 "파일 3개"와 변경 탭 "4개"가 다름)

## 결정
프롬프트 훅을 받으면 응답하기 전에 작업 트리 스냅샷을 찍고(최대 1.5초 기다림), Stop 훅에서 다시 찍어 둘의 차이를 `turn.changes` 이벤트로 원장에 남긴다. 타임라인 턴 카드는 이 목록(A/M/D)을 보여주고, 없을 때만 편집 도구가 보고한 파일을 쓴다.

## 이유
실측: Claude가 README·PLAN·AGENTS는 Edit 도구로, 작업일지는 `cat >>`(Bash)로 고쳤다. 훅으로는 Bash 변경이 안 보여 턴 카드가 3개, git 기반 변경 탭이 4개를 보였다. 사람에게 보여주는 숫자가 서로 다르면 둘 다 믿지 않게 된다.

## 대안
- Bash 명령 문자열을 해석해 파일 추측: 불완전하고 깨지기 쉽다.
- 턴 끝에만 스냅샷: 시작점이 없어 그 턴의 변경을 가를 수 없다.

## 결과와 대가
프롬프트마다 Claude 시작이 스냅샷 시간만큼(보통 수백 ms, 최대 1.5초) 늦어질 수 있다. 같은 폴더에서 탭 여러 개가 동시에 일하면 서로의 변경이 섞인다. 턴 중간에 Claude가 커밋해도 tree끼리 비교하므로 결과는 같다(테스트로 확인). 이 이벤트는 그 순간의 관찰이라 나중에 다시 계산할 수 없으므로 원장에 저장한다(파생값 저장 금지 원칙의 예외가 아니다).
