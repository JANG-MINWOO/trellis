# ADR-0024: 동작 명세는 영역별 마크다운, 항목에 고정 번호

- 상태: 채택
- 날짜: 2026-10-10
- 결정한 사람: 에이전트 제안 (PLAN M4) → 미누 진행 승인

## 결정
동작 명세는 대상 저장소의 `docs/specs/`(프로젝트 설정에서 바꿈, 비우면 끔)에 기능 영역 하나당 파일 하나로 둔다. 파일은 `# 영역 이름`, `## 동작`, `## 불변식` 두 절과 `- [B-001] 문장` 형태의 항목으로 된다. 동작은 EARS("WHEN …, THE SYSTEM SHALL …"), 불변식은 "항상 지켜야 하는 규칙" 한 문장이다. 번호는 프로젝트 전체에서 B-/I-별로 이어지고, 바뀌어도 번호는 유지된다. 턴 분석이 찾은 동작 변경(추가·변경·삭제)과 작업 의도의 "하면 안 되는 것"은 후보로 올라오고, 사람이 문장과 영역을 고쳐 "반영"해야 파일에 들어간다. 테스트 파일에 번호(`B-003`)를 적으면 Trellis가 찾아 항목 옆에 연결된 테스트 수를 보여준다.

## 이유
동작은 업무 용어 층(ADR-0012)이라 비개발자도 읽어야 하므로 코드 밖, 사람이 읽는 마크다운이어야 한다. 고정 번호가 있어야 변경·삭제 대상과 테스트를 가리킬 수 있다. 번호 언급으로 연결하면 테스트 프레임워크·언어와 무관하다(스택 무관 원칙).

## 대안
- Gherkin(.feature): 특정 테스트 도구를 전제한다.
- JSON/YAML 명세: 사람이 읽고 고치기 어렵다.
- 명세를 Trellis 안에만 저장: 저장소를 떠나면 사라지고, 다른 사람·에이전트가 못 본다.

## 결과와 대가
Trellis가 다시 쓰는 파일이므로 항목 형식을 벗어난 자유 서술은 다음 반영 때 사라질 수 있다(파일 머리에 그렇게 적어 둔다). 테스트 연결은 번호를 적는 습관에 기대고, 테스트가 그 동작을 실제로 검증하는지는 보지 않는다.
