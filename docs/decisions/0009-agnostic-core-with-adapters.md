# ADR-0009: 스택·에이전트 무관 핵심 + 어댑터

- 상태: 채택
- 날짜: 2026-10-09
- 결정한 사람: 미누 ("추상화를 잘해야 한다")

## 결정
핵심 모델(프로젝트, 세션, 정규화 이벤트, 의도, 변경 묶음, 결정, 스펙, 규칙, 건강 지표)은 언어·프레임워크·에이전트를 가리지 않게 만든다. 차이는 에이전트 어댑터(실행 명령·이벤트 브리지·정규화)와 스택 어댑터(import 추출·규칙 도구 연결)로 붙인다. v1의 에이전트 어댑터는 Claude Code 하나다.

## 이유
대상이 Godot 게임(GDScript), Electron 앱(TS), 마크다운+셸 하네스, Spring 백엔드처럼 성격이 다르다. 핵심을 의도 레이어에 두면 대부분 스택과 무관해진다.

## 대안
스택 하나(Spring)로 좁히기: 코드 수준 영향 분석에는 맞지만, 의도 레이어 중심 설계에서는 필요 없다.

## 결과와 대가
초기 구현에서 인터페이스를 먼저 그어야 한다. 단, 구현이 하나뿐인 추상화는 최소한으로 둔다(인터페이스와 Claude Code 구현 하나).
