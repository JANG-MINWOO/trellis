# ADR-0033: 파일 트리의 변경 표시는 항상 마지막 커밋 기준으로 한다

- 상태: 채택
- 날짜: 2026-10-18
- 결정한 사람: 에이전트 제안 → 미누 승인

## 결정
왼쪽 파일 트리의 변경 표시(A·M·R·T와 폴더 점)는 오른쪽 변경 탭에서 고른 기준과 상관없이 항상 마지막 커밋(`HEAD^{tree}`)과 지금 작업 트리를 비교해 붙인다. git status와 같은 뜻이라, 커밋하면 표시가 사라진다. 오른쪽 변경 탭은 그대로 "Claude 시작 이후(기본) / 마지막 커밋 이후"를 고를 수 있다.

## 이유
파일 트리가 변경 탭의 기준을 따르고 있어서, 기본값인 "Claude 시작 이후"에서는 커밋한 뒤에도 M이 남았다. 사람은 파일 트리의 M을 "커밋하지 않은 변경"으로 읽어서, 커밋이 안 된 것처럼 보였다(미누가 실제로 겪음). "이번 실행에서 에이전트가 무엇을 바꿨나"는 변경 탭이 보여 준다.

## 대안
- 지금처럼 변경 탭의 기준을 따르기: 커밋 뒤에도 M이 남아 혼란스럽다.
- 파일 트리에 기준 선택을 따로 두기: 고를 것이 늘고, 두 화면이 서로 다른 기준이라는 것을 사람이 기억해야 한다.
- 파일 트리 전용 조회를 따로 두기: 같은 작업 트리 스냅샷을 두 번 찍게 된다.

## 결과와 대가
변경 조회(`ChangeReport`)가 패널용 묶음과 함께 파일 트리용 `sinceHead`(경로와 상태)를 같이 돌려준다. 작업 트리 스냅샷은 한 번만 찍고, 패널 기준이 마지막 커밋과 다를 때만 `git diff-tree --name-status`를 한 번 더 돈다(줄 수 계산 없음). 인덱스는 그대로 두고 브랜치만 옮기는 명령(`git reset --soft` 등) 뒤에도 표시가 바로 맞도록, 프로젝트 감시가 `.git`의 `HEAD`·`index`에 더해 `refs/heads/`와 `packed-refs`도 본다. 커밋하지 않은 변경은 두 화면에서 같은 뜻이지만, "Claude 시작 이후"를 보고 있으면 변경 탭과 파일 트리의 파일 수가 다를 수 있다.
