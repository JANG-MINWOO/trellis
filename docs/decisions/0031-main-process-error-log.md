# ADR-0031: 메인 프로세스 오류는 데이터 폴더의 로그 파일에 남긴다

- 상태: 채택
- 날짜: 2026-10-16
- 결정한 사람: 에이전트 제안 (0.2.0 고정 점검) → 미누 진행 승인

## 결정
메인 프로세스에는 `src/main/lib/log.ts` 하나로 오류를 남긴다. 파일은 데이터 폴더의 `logs/main.log`이고(개발 빌드는 `Trellis-dev` 쪽), 시작할 때 1MB를 넘었으면 `main.1.log`로 한 번만 돌린다. 아무도 기다리지 않는 작업(훅 처리, 턴 마무리, 기준점 스냅샷, 검사 미리 준비)의 실패는 `.catch(() => undefined)`로 삼키지 않고 `logFailure(범위, 설명)`로 남긴다. 처리되지 않은 Promise 거부도 남긴다. 앱 시작이 실패하면 로그에 남긴 뒤 오류 창을 띄우고 종료한다.

## 이유
점검해 보니 메인 프로세스에 로그가 하나도 없었고, 8곳에서 오류를 조용히 버렸다. 이벤트가 사라지거나 턴 마무리가 실패해도 알 길이 없었다. 시작 오류는 받는 곳이 없어서, 창 없이 단일 실행 잠금만 쥔 프로세스가 남았다. 그 상태에서는 다시 실행해도 아무것도 뜨지 않았다.

## 대안
- electron-log 같은 라이브러리: 회전·여러 출력 대상까지 필요하지 않다. 50줄이면 된다.
- Electron의 `app.getPath('logs')`: 앱 이름 기준이라 안정 빌드와 개발 빌드가 같은 폴더를 쓴다(ADR-0011과 어긋남).
- 화면에 오류 알림: 백그라운드 작업 실패마다 알림을 띄우면 시끄럽다. 사람이 고칠 수 있는 오류는 지금처럼 패널·알림으로 보여 준다.

## 결과와 대가
문제가 생기면 `logs/main.log`를 보면 된다. 로그에는 오류 메시지와 스택만 쓰고 프롬프트·명령 내용은 쓰지 않는다. 로그도 이벤트 원장처럼 로컬에만 있고 밖으로 보내지 않는다. renderer 오류는 아직 남기지 않는다.
