# ADR-0027: 작업 끝 검사는 Stop 훅에 block으로 답해 되돌려 보낸다

- 상태: 채택
- 날짜: 2026-10-10
- 결정한 사람: 에이전트 제안 (PLAN M3) → 미누 진행 승인

## 결정
프로젝트 설정 "작업 끝 검사"를 켜면, Claude가 멈출 때(Stop 훅) Trellis가 답하기 전에 검사한다. (1) 구조 규칙: 턴 시작 트리와 지금 트리를 같은 규칙(턴 시작 시점의 `.trellis/`)으로 검사해, 이번 턴이 새로 만든 위반만 고른다. 이미 기준을 넘던 파일·폴더도 10% 이상(파일 10줄·폴더 3개 이상) 커지면 새 위반으로 본다. (2) 검사 명령(예: `npm test`): 사용자의 셸로 프로젝트 폴더에서 실행, 100초 제한. 문제가 있으면 `{"decision":"block","reason":…}`으로 답해 Claude가 이유를 읽고 고치게 한다. 다시 멈출 때(`stop_hook_active`)는 검사하지 않아 한 턴에 한 번만 되돌린다. 완료 알림은 되돌리지 않을 때만 보낸다. Stop 훅 제한 시간은 120초, 브리지는 115초.

## 이유
규칙을 문서로만 두면 지켜지지 않는다(기계적 집행 원칙). 턴 단위로 "새로 만든 것"만 막으면 기존 빚 때문에 일이 멈추지 않는다(래칫). 규칙을 턴 시작 시점 것으로 쓰면 에이전트가 규칙 파일을 느슨하게 고쳐 통과하는 길이 막힌다(`.trellis/**`는 확인 필요 영역에도 넣었다). 한 번만 되돌리면 고칠 수 없는 문제로 무한 반복하지 않는다.

## 대안
- 검사 결과를 보여주기만: 사람이 매번 다시 지시해야 한다.
- 매 도구 호출마다 검사(PostToolUse): 느리고, 작업 중간의 일시적 상태를 막는다.
- 기준선 없이 전체 위반으로 막기: 기존 저장소에서는 첫 턴부터 막힌다.

## 결과와 대가
검사 명령이 오래 걸리면 턴이 그만큼 늦게 끝난다(상태 바에 "작업 끝 검사 중"). 사용자가 입력한 검사 명령은 셸 문자열이라 argv 원칙의 예외다 — Trellis가 조립하지 않고 사용자가 쓴 그대로 셸에 넘긴다. 셸이 시작한 하위 프로세스까지 제한 시간에 함께 끝낸다.
