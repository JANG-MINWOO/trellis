# ADR-0034: 작업 의도는 작업 단위로 시작하고 마무리한다

- 상태: 채택 (프로젝트마다 작업 하나·새 대화면 묻기는 ADR-0035의 대화별 작업으로 대체)
- 날짜: 2026-10-18
- 결정한 사람: 에이전트 제안 → 미누 승인 ("그 내용대로 업데이트 한번 쭉 진행해줄래?")

## 결정
- 의도를 "프로젝트에 마지막으로 적힌 글"이 아니라 작업 단위로 다룬다. 작업은 진행 중이거나 마무리됐다. 의도 카드에서 다듬기(같은 작업의 의도를 고침), 마무리, 새 작업을 고른다. 마무리한 뒤의 턴에는 의도가 붙지 않는다. 마무리 요약에서 다시 열 수 있다.
- 원장에 더하는 것: `intent.set`에 작업 id(`taskId`)와, 앞선 턴을 새 작업에 넣을 때의 시작 시각(`from`). `intent.done`(작업 id, 끝난 시각 `at`)과 `intent.continue`(이어서 한다고 답함). 작업의 범위, 턴이 속한 작업, 누적 비교, 다시 물을 때는 모두 원장에서 계산한다. 작업 id가 없는 예전 의도는 하나하나가 작업이다.
- 예측 비교는 작업 전체로 쌓는다. 턴 카드에는 그 작업에서 처음 나온 예상 밖 영역만 보이고, "그대로인 곳"은 마무리 요약에만 보인다. 어떤 영역이 예상한 곳이었는지는 그 영역이 처음 바뀐 턴의 의도로 판단한다. 나중에 예측을 고쳐 놓친 것을 덮지 않게.
- 다시 묻는 때. 터미널은 막지 않고 의도 카드에 질문 한 줄을 띄운다.
  - 진행 중인 작업에 턴이 있었는데 새 대화가 시작되거나 `/clear` 했을 때
  - 마지막 활동 뒤 6시간 넘게 지났을 때
  - 분석이 이번 요청을 의도와 다른 작업이라고 판단했을 때
  - 분석 판단이 없거나 불확실한데, 한 턴이 예상한 곳은 하나도 안 건드리고 새 영역만 바꿨을 때

  답은 이어서 / 마무리 / 새 작업이다. 마무리와 새 작업은 질문이 생긴 시점을 경계로 쓴다. 그 뒤의 턴은 옛 작업에서 빠지고, 새 작업을 적으면 그 작업으로 들어간다.
- 턴 분석(ADR-0023)의 같은 호출에서 두 가지를 더 묻는다. 이번 요청이 의도와 이어지는지(yes/no/unclear), "하면 안 되는 것" 가운데 diff가 어긴 것으로 보이는 줄. 둘 다 AI 추정으로 표시한다. Claude 호출은 늘지 않는다.
- 화면이 들고 있는 이벤트 수 제한(최근 2000개)에서 `intent.*` 이벤트는 빼지 않는다. 오래 걸리는 작업의 의도가 창 밖으로 밀려 사라지지 않게.

## 이유
실제 작업은 한 번에 끝나기도, 여러 턴에 걸치기도, 같은 대화에서 다른 일로 넘어가기도 한다. 의도가 하나뿐이고 끝이 없으면 옛 의도가 새 일에 계속 붙어 거짓 "예상 밖" 경고가 나고, 분석도 옛 의도를 기준으로 판단한다. 턴 단위 비교는 여러 턴 작업에서 "그대로인 곳"을 매 턴 잘못 보여 준다. 마무리는 남은 결정 카드와 불변식을 챙기기 좋은 순간이기도 하다.

## 대안
- 프롬프트마다 의도를 묻기: 한 번에 끝나는 작업과 이어지는 턴에서 너무 시끄럽다.
- AI가 작업 경계를 정하기: 경계는 사람이 정해야 의도가 사람의 것으로 남는다. AI 판단은 질문을 띄우는 신호로만 쓴다.
- 탭마다 작업을 두기: 맞는 방향이지만, 탭 여럿이 같은 폴더를 동시에 고칠 때 턴 변경이 섞이는 한계와 같이 풀어야 해서 다음 단계로 미룬다. 지금은 프로젝트마다 진행 중인 작업이 하나다.

## 결과와 대가
- 새 Claude 탭을 열어도 "새 대화"로 보고 한 번 묻는다. 이어서를 누르면 다음 신호까지 조용하다.
- 분석이 꺼져 있으면 다른 작업인지는 예측 영역으로만 짐작한다.
- 누적 비교와 요약은 화면에 있는 이벤트(최근 2000개와 의도) 안의 턴으로 계산한다. 아주 긴 작업은 앞쪽 턴이 빠질 수 있다.
- ADR-0025의 턴 단위 비교를 대체한다.
