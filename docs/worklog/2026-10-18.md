# 2026-10-18 — 파일 트리 변경 표시 기준

미누 제보: 커밋했는데 왼쪽 파일 트리의 M이 그대로 남았고, Trellis를 껐다 켜니 사라졌다.

## 원인
파일 트리의 표시가 오른쪽 변경 탭의 기준을 그대로 따랐다. 기준은 앱 전체에 하나이고 기본값이 "Claude 시작 이후"(Claude를 띄운 순간의 스냅샷)라, 커밋해도 "그 뒤로 바뀐 파일"이라는 사실은 그대로여서 M이 남았다. 껐다 켜면서 Claude를 다시 띄워 기준점이 새로 잡혔기 때문에 사라졌다. 커밋 감지 자체는 정상이었다(`git commit`은 `.git/index`를 다시 쓴다, 직접 확인).

## 한 일
- 파일 트리 표시를 변경 탭 기준과 떼어 항상 마지막 커밋 기준으로 바꿨다(ADR-0033, 미누 승인). 변경 조회가 HEAD 대비 경로·상태(`sinceHead`)를 같이 돌려주고, 파일 트리는 그것만 본다. 작업 트리 스냅샷은 한 번만 찍고, 패널 기준이 HEAD와 다를 때만 `diff-tree --name-status`를 한 번 더 돈다. 변경 탭은 그대로 두 기준을 고르고 기본값도 같다.
- 프로젝트 감시가 `.git/refs/heads/`와 `packed-refs`도 본다. `git reset --soft`처럼 인덱스는 두고 브랜치만 옮기면 `.git/index`가 바뀌지 않아 다시 계산하지 않았다(직접 확인).
- 테스트: 단위·통합 121개 → 123개(커밋 뒤 파일 트리 표시는 비고 패널 목록은 남는지, 감시 대상 경로). smoke e2e에 "커밋하면 파일 트리 표시가 사라지고 변경 탭에는 남는다"를 넣었다. 파일 트리를 예전 코드로 돌려 이 검사가 실패하는 것도 확인했다. e2e 3개 통과.
- 문서: PLAN(§5 개념 표, F5, §8 0.2.0 고정에 항목 추가), README 두 개, ADR 목록.
- 안정 빌드: `install:local`. Trellis가 실행 중이라 종료할 때 교체되고 다시 열린다.

## 정한 것
- ADR-0033: 파일 트리 표시는 git status와 같은 뜻(마지막 커밋 기준), "이번 실행에서 바뀐 것"은 변경 탭.

## 문제·남은 것
- 프로젝트가 큰 저장소의 하위 폴더면 `.git`이 감시 범위 밖이라, 파일은 그대로 두고 커밋만 하면 표시가 바로 갱신되지 않는다. 다음 파일 변경이나 Claude 이벤트가 오면 맞춰진다. 전부터 있던 한계다(변경 탭의 "마지막 커밋 이후"도 같다). 파일 트리의 새로 고침 버튼은 목록만 다시 읽고 변경 표시는 다시 계산하지 않는다.
- "Claude 시작 이후"를 보고 있으면 변경 탭과 파일 트리의 파일 수가 다를 수 있다(의도한 차이).

## 다음 할 일
1. (미누) 교체된 안정 빌드에서 커밋 뒤 M이 사라지는지 확인, 괜찮으면 `v0.2.0` 태그를 달지 정한다.
2. (미누) hearthwild 실험 기준점, 결정 카드 정탐/오탐 기록(2026-10-16 작업일지 참고).
3. (에이전트) 제보된 버그 수정, 그다음 PLAN M5.

# 2026-10-18 (오후) — 작업 단위 의도

미누 점검 요청: 의도를 적고 일할 때 한 번에 끝나는 작업, 3~4턴 이어 가는 작업, 같은 대화에서 다른 의도의 작업으로 넘어가는 경우가 있는데, 끊어 가며 작업하고 마무리 상태를 남기고 다시 묻는 경로가 있는가. 점검 결과 없었다. 의도는 프로젝트에 마지막으로 저장한 글 하나였고(끝내거나 비울 수도 없음), 다음 의도를 적을 때까지 모든 턴에 붙었다. 예측 비교는 턴 하나 단위라 여러 턴 작업에서 "그대로인 곳"이 매 턴 잘못 떴고, 다른 일로 넘어가면 거짓 "예상 밖" 경고가 나고 분석도 옛 의도로 판단했다. 미누가 제안대로 진행하라고 했다.

## 한 일
- ADR-0034. 의도를 작업 단위로 다룬다. 원장에 `intent.set`의 `taskId`·`from`, `intent.done`(`at`), `intent.continue`를 더했고, 작업 범위·턴 소속·누적 비교·물을 때는 모두 원장에서 계산한다(`shared/tasks.ts`, `shared/task-check.ts`). 작업 id 없는 예전 의도는 하나하나가 작업이다.
- 의도 카드를 나눴다(`IntentCard`, `IntentForm`, `TaskDetails`, `TaskCheckNotice`).
  - 진행 중: 다듬기, 마무리, 진행 상황(예상한 곳 체크, 예상 밖 영역, 이 작업의 처리 안 한 결정·동작 카드, 하면 안 되는 것 경고).
  - 마무리 뒤: 요약과 다시 열기, 새 작업 적기.
- "이 작업을 이어서 하나요?"(이어서·마무리·새 작업)를 의도 카드에 띄운다. 터미널은 막지 않는다.
  - 띄우는 때: 턴이 있던 작업 뒤 새 대화·`/clear`, 6시간 넘게 쉼, 분석이 요청을 다른 작업으로 읽음, 분석 판단이 없을 때 예상한 곳을 하나도 안 건드리고 새 영역만 바꾼 턴.
  - 마무리와 새 작업은 질문이 생긴 시점을 경계로 쓴다. 그 뒤의 턴은 새 작업으로 들어간다.
- 타임라인: "새 작업", "의도를 다듬었어요", "작업 마무리 · 턴 N · 예상 밖 N" 표시. 턴 카드의 예측 줄은 그 작업에서 처음 나온 예상 밖 영역만 보이고, 모두 예상한 곳 안이면 그렇게 표시한다. 분석이 다른 작업으로 읽은 턴과 하면 안 되는 것을 건드렸을 수 있는 턴에 배지.
- 턴 분석(같은 호출)에 `intentFit`(yes/no/unclear)과 `mustNotBroken`을 더했다. 분석에 넘기는 의도도 그 턴이 속한 작업의 의도로 바꿨다(목표·하면 안 되는 것만, 예상 영역은 빼고). 실제 claude(haiku)로 새 스키마를 한 번 돌려 확인했다. 로그인 잠금 의도에 로고 이름 바꾸기 요청을 넣자 `intentFit: "no"`.
- 이벤트 창: main이 읽을 때 창(2000개) 밖의 오래된 `intent.*` 줄도 같이 읽고(줄 문자열로 먼저 걸러 나머지는 파싱하지 않음), renderer도 창을 줄일 때 의도 이벤트는 남긴다. 오래 걸리는 작업의 의도가 창 밖으로 밀려 사라지지 않게.
- 테스트: 단위·통합 123개 → 144개(작업 계산, 물을 때, 누적·턴별 예측, 분석 질문, 입력 검증, 이벤트 창, JSONL 읽기). intent e2e를 늘렸다. 두 번째 턴(같은 영역이라 턴 카드에 예상 밖 없음, 하면 안 되는 것 경고), 다른 작업 요청(질문이 뜨고 새 작업이 그 턴을 가져감), 마무리와 다시 열기까지 확인한다. 스크린샷으로 화면을 확인했다.
- 문서: PLAN(사용 흐름, §5 이벤트·작업 개념, §6 분석, F4·F9, 새 체크리스트 "작업 단위 의도"), README 두 개(의도 설명, 알려진 한계), ADR-0025 상태.
- 실제 원장(안정 빌드의 이 저장소 프로젝트)에 새 계산을 읽기 전용으로 돌려 봤다. 10-16의 "0.2.0 고정" 의도가 오늘 작업에도 붙어 있었고, 새 검사가 "한동안 쉬었다가 다시 왔어요"로 오늘 첫 턴을 경계로 잡는다. 그 작업의 예상 밖 영역이 36개라 의도 카드의 영역 표시는 8개까지 보이고 나머지는 "+N"으로 줄였다.
- `install:local`: Trellis 실행 중에 두 번 돌리면 교체 대기 도우미가 둘 남아, 종료할 때 예전 빌드가 이길 수 있었다(오후 3시의 `c6bd56a` 대기가 실제로 남아 있었다). 새 대기를 걸기 전에 이전 도우미를 끄고 그 임시 빌드를 지운다. 다시 돌려 이전 대기가 취소되고 하나만 남는 것을 확인했다.
- 안정 빌드: `0.2.0+01c2899` 교체 대기. Trellis를 종료하면 교체되고 다시 열린다.

## 정한 것
- ADR-0034: 작업 단위 의도. 경계는 사람이 정하고, AI 판단과 시간·대화 신호는 질문을 띄우는 데만 쓴다. 탭마다 작업은 다음 단계.

## 문제·남은 것
- 진행 중인 작업은 프로젝트마다 하나다. 탭 둘에서 다른 일을 하면 같은 의도가 붙는다(탭마다 작업은 턴 변경이 섞이는 문제와 같이 다룰 것).
- 새 Claude 탭을 열어도 "새 대화"로 보고 한 번 묻는다.
- 분석이 꺼져 있으면 다른 작업인지는 예측 영역으로만 짐작한다. 예측을 안 고른 작업은 그 신호도 없다(새 대화·쉼 신호만).
- 누적 요약은 화면에 있는 이벤트 안의 턴으로 계산한다. 아주 긴 작업은 앞쪽 턴이 빠질 수 있다.
- 버전은 그대로 0.2.0이다. 태그와 버전 올리기는 미누가 정한다.
