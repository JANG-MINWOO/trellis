# 2026-10-18 — 파일 트리 변경 표시 기준

미누 제보: 커밋했는데 왼쪽 파일 트리의 M이 그대로 남았고, Trellis를 껐다 켜니 사라졌다.

## 원인
파일 트리의 표시가 오른쪽 변경 탭의 기준을 그대로 따랐다. 기준은 앱 전체에 하나이고 기본값이 "Claude 시작 이후"(Claude를 띄운 순간의 스냅샷)라, 커밋해도 "그 뒤로 바뀐 파일"이라는 사실은 그대로여서 M이 남았다. 껐다 켜면서 Claude를 다시 띄워 기준점이 새로 잡혔기 때문에 사라졌다. 커밋 감지 자체는 정상이었다(`git commit`은 `.git/index`를 다시 쓴다, 직접 확인).

## 한 일
- 파일 트리 표시를 변경 탭 기준과 떼어 항상 마지막 커밋 기준으로 바꿨다(ADR-0033, 미누 승인). 변경 조회가 HEAD 대비 경로·상태(`sinceHead`)를 같이 돌려주고, 파일 트리는 그것만 본다. 작업 트리 스냅샷은 한 번만 찍고, 패널 기준이 HEAD와 다를 때만 `diff-tree --name-status`를 한 번 더 돈다. 변경 탭은 그대로 두 기준을 고르고 기본값도 같다.
- 프로젝트 감시가 `.git/refs/heads/`와 `packed-refs`도 본다. `git reset --soft`처럼 인덱스는 두고 브랜치만 옮기면 `.git/index`가 바뀌지 않아 다시 계산하지 않았다(직접 확인).
- 테스트: 단위·통합 121개 → 123개(커밋 뒤 파일 트리 표시는 비고 패널 목록은 남는지, 감시 대상 경로). smoke e2e에 "커밋하면 파일 트리 표시가 사라지고 변경 탭에는 남는다"를 넣었다. 파일 트리를 예전 코드로 돌려 이 검사가 실패하는 것도 확인했다. e2e 3개 통과.
- 문서: PLAN(§5 개념 표, F5, §8 0.2.0 고정에 항목 추가), README 두 개, ADR 목록.
- 안정 빌드: `install:local`. Trellis가 실행 중이라 종료할 때 교체되고 다시 열린다.

## 정한 것
- ADR-0033: 파일 트리 표시는 git status와 같은 뜻(마지막 커밋 기준), "이번 실행에서 바뀐 것"은 변경 탭.

## 문제·남은 것
- 프로젝트가 큰 저장소의 하위 폴더면 `.git`이 감시 범위 밖이라, 파일은 그대로 두고 커밋만 하면 표시가 바로 갱신되지 않는다. 다음 파일 변경이나 Claude 이벤트가 오면 맞춰진다. 전부터 있던 한계다(변경 탭의 "마지막 커밋 이후"도 같다). 파일 트리의 새로 고침 버튼은 목록만 다시 읽고 변경 표시는 다시 계산하지 않는다.
- "Claude 시작 이후"를 보고 있으면 변경 탭과 파일 트리의 파일 수가 다를 수 있다(의도한 차이).
