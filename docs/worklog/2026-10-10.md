미누 요청: "핵심 아직 만들지 않았는데 그 M2~M4 까지 이어서 쭉 진행해줘. 그걸 다 만들고 버그를 하나씩 잡아가면서 버전을 픽스해야 할 것 같아."

## 한 일

**M2 결정 감지 → 기록** (ADR-0023)
- 턴이 끝나고(Stop) 파일이 바뀌었으면, 그 턴의 diff(확인 필요 영역 먼저, 잠금 파일·바이너리 제외, 약 4만 자 제한)·요청·마지막 메시지·의도·기존 결정 제목·명세 항목을 넣어 `claude -p --restricted --strict-mcp-config --tools "" --no-session-persistence --json-schema`를 임시 폴더에서 한 번 실행. 결정(최대 3)과 동작 변경(최대 5)을 한 번에 받는다.
- 결과 정리(`toCandidates`): 개수 제한, 바뀌지 않은 파일 제거, 이미 기록·대기·기각된 제목 제외, 없는 명세 번호를 가리키는 변경은 추가로.
- 결정 카드: 결과와 대가를 앞에, AI 추측·대안·파일은 접어 둠. 이유는 사람이 써야 "기록하기"가 켜진다. "AI 추측을 이유로 기록"은 따로 누르고, 기록 파일에 "AI 추측"으로 남는다. 기록하면 결정 폴더에 `NNNN-제목.md`(번호 이어 쓰기, `wx`로 덮어쓰기 방지). 폴더를 비우면 원장에만.
- 확인 필요 영역(glob, 프로젝트 설정, 기본값에 auth·payment·migrations·.env·workflows·`.trellis/**`)은 분석을 꺼도 카드.
- 설정: 프로젝트별 분석 켜기/끄기, 분석 모델(기본 sonnet), 사용 횟수·실패 표시.
- 실측(실제 claude, sonnet): 로그인 잠금 + bcrypt 교체 + 마이그레이션 + README 오타 예제에서 7.7초, 약 $0.03. "요청 범위를 넘어 SHA-256을 bcrypt로 바꿔 기존 사용자 로그인이 막힐 수 있다"를 결정으로 잡고, README 오타는 무시했다.

**M4 의도 레이어** (ADR-0024, 0025)
- 동작 명세: `docs/specs/<영역>.md`, `## 동작`(EARS)·`## 불변식`, `- [B-001] 문장`. 번호는 프로젝트 전체에서 이어짐. 반영은 해당 줄만 고친다(사람이 쓴 설명 유지).
- 동작 탭: 분석이 찾은 동작 변경을 사람이 문장·영역을 고쳐 "반영". 테스트 파일에서 번호를 찾아 연결 수 표시(명세·문서 파일은 제외 — 처음엔 명세 파일 자신이 테스트로 잡히는 버그가 있었다).
- 작업 의도: 하려는 것 / 하면 안 되는 것 / 바뀔 것 같은 곳(영역 칩). 턴 카드에 "예상 밖 변경"·"그대로인 곳". 하면 안 되는 것 → 불변식 후보.
- 문서 어긋남(ADR-0028): 살아 있는 문서(루트 md, AGENTS/CLAUDE.md, docs 최상위, 명세)가 가리키는데 없는 경로. minu-future 복제본으로 오탐을 확인해 줄였다(`…` 자리표시, 코드 안 링크 예시, 빈 폴더).

**M3 구조 규칙 + 건강 + 가드** (ADR-0026, 0027, 0028, 0029)
- 규칙 엔진(`src/main/features/rules/`): 긴 파일, 폴더당 코드 파일 수, 중복(의미 있는 줄 12줄 창), 순환(Tarjan, 반복형), 경로 경계(glob). import 추출 TS/JS(+tsconfig paths·별칭, `.js`→`.ts`), Python(상대 import 포함), GDScript `res://`, Java/Kotlin, 셸 source.
- 파일은 git 트리에서(`ls-tree` + `cat-file --batch`), 내용(blob) 단위로 사실(fact) 캐시. git 아닌 폴더는 직접 읽기.
- 설정 `.trellis/rules.json`(JSONC 허용, 없으면 기본값), 기준선 `.trellis/baseline.json`(사람이 "기준선 얼리기"로).
- 가드: Stop에서 턴 시작·끝 트리를 턴 시작 시점 규칙으로 비교 → 새 위반(+기준 넘던 파일이 크게 커진 것) + 검사 명령 실패 → `{decision:"block", reason}`. `stop_hook_active`면 다시 막지 않음. 알림은 막지 않을 때만. 검사 중 상태 바 표시. 되돌린 턴은 마지막 검사를 항상 기록(처음엔 고친 뒤에도 "규칙 위반 1"이 남는 버그).
- 브리지가 핸들러의 JSON을 응답 본문으로 돌려줌, Stop만 115초까지 기다림(훅 제한 120초).
- 건강 패널: 새 위반(규칙별), 기준선, 지난주 대비(하루 한 번 `health.snapshot`), 문서 어긋남, 큰 파일·밀집 폴더, 시작 템플릿 창. 파일 변경에 1.5초 묶어서 갱신.
- 성능 측정(로컬 복제·합성 저장소): 1.1천 파일 갱신 약 0.5초(대부분 스냅샷), 6.8천 파일 약 0.7초(분석 CPU 약 0.5초, 메인 프로세스), Trellis 약 0.1초.

## 문제·남은 것
- 분석은 백그라운드라 결정 카드가 턴이 끝나고 몇 초 뒤에 뜬다.
- 규칙 분석이 메인 프로세스에서 돈다. 1만 파일 이상은 M5에서 작업 스레드로.
- 셸 탭 입력 문제는 여전히 미누 확인 대기(M1.1).
- 실제 claude(haiku)로 가드·분석 전 구간 확인(`real-claude.spec.ts` 두 번째 테스트, 39초): 60줄 파일 → Stop에 block → Claude Code가 "Stop hook error: [Trellis 검사] … numbers.js: 60줄이에요 (기준 30줄)"를 보여주고 Claude가 파일을 둘로 나눔 → 두 번째 Stop(`stop_hook_active`)은 통과 → 마지막 검사 위반 0 → 분석 9.2초, 결정 1("요청과 달리 두 파일로 나누고 다시 내보냄")·동작 1. 같은 턴의 prompt_id가 유지되는 것도 확인.
- Claude Code는 block 이유를 "Stop hook error"라는 이름으로 보여준다(Claude 쪽 표기). 사용자의 다른 Stop 훅도 함께 돈다("Ran 4 stop hooks").
- 수정 자동 허용 모드에서는 Claude가 고칠 때 쓰는 Bash 명령에 승인이 필요하다 — 사람이 승인해야 이어진다(정상 동작).
