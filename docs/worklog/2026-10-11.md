# 2026-10-11 — 저장소 공개 (MIT)

미누 요청: "메일 그대로. 회사 이름 지우고 MIT. 이미 남아버린 것들은 커밋 히스토리 정리까지."
배경: 팔 계획이 없고, Electron 앱은 설치 파일 안의 코드가 어차피 읽힌다는 걸 확인한 뒤 공개하기로 했다.

## 한 일
- 공개 전 점검: 이력 전체에서 키·토큰 패턴 없음. 회사 계정 이름은 ADR-0006의 한 줄에만 있었고, 첫 커밋부터 41개 커밋 전부에 들어 있었다. 태그·릴리스·PR·Actions 비밀값은 없었다.
- MIT `LICENSE`, `package.json` license. 영어 README(`README.en.md`, ADR-0007의 "공개할 때 영어 README").
- CI 권한: 기본은 읽기, 쓰기는 태그 릴리스 작업에만(공개 저장소는 누구나 PR을 보낼 수 있다).
- ADR-0030. ADR-0006·0010 상태, ADR-0021 조건 ②, PLAN(M0 저장소 항목, M5 배포 채널·영어 README·라이선스) 갱신.
- 이력 다시 쓰기: 임시 복제본에서 `git filter-repo --replace-text`로 회사 계정 이름을 지웠다. 이전 GitHub 저장소는 `trellis-private-archive`로 이름을 바꿔 보관(비공개, 읽기 전용)하고, 새 `JANG-MINWOO/trellis`에 다시 쓴 이력을 올린 뒤 공개로 바꿨다. 같은 저장소에 강제 푸시하면 이전 커밋이 해시로 계속 열리기 때문이다.
- 로컬 저장소는 새 이력으로 맞췄다(`git gc`는 하지 않음 — 실행 중인 Trellis의 변경 기준점 객체를 지우지 않으려고).
- 전날(10-10) 미누 확인: ADR-0014, 0023~0029 동의. 성능 측정 중 실수로 커밋한 `bench-touch.txt` 삭제.

## 정한 것
- ADR-0030: MIT로 공개, 커밋 메일은 그대로, 회사 이름은 이력에서 제거.

## 문제·남은 것
- 이 날 이전 문서에 적힌 커밋 해시(예: 작업일지의 `0.2.0+e08a537`)는 이전 이력의 것이라 지금 저장소에는 없다.
- 이전 저장소의 Actions 기록은 보관 저장소에 남아 있다(비공개).
