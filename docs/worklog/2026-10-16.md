# 2026-10-16 — 0.2.0 고정 점검

미누 요청: 작업일지와 PLAN을 확인하고, 완성도와 구조를 점검해서 모자란 것과 버그를 잡아 0.2.0을 제대로 고정한다. 구현된 기능의 기획은 바꾸지 않는다. PLAN §8 "0.2.0 고정".

## 점검한 방법
- `npm run check`, `npm run e2e`(smoke·intent·guard), CI 상태를 먼저 확인했다. 모두 통과였다.
- main/shared, renderer, 문서와 코드의 일치를 세 갈래로 나눠 읽었다. 심각한 지적(깨진 파일이 빈 값으로 덮임, 시작 실패, stdin 오류, 프로젝트 전환 경쟁)은 코드에서 직접 확인한 뒤 고쳤다.

## 한 일

**버그** (`fix(main)`, `fix(renderer)`)
- `readJson`이 "파일 없음"과 "읽을 수 없음"을 구분하지 않아, `projects.json`이 깨지면 빈 목록으로 읽고 다음 저장에서 덮어썼다. 이제 깨진 파일은 `.corrupt-<시각>`으로 옮기고 로그를 남긴다. 같은 파일 쓰기는 차례대로, 임시 파일 이름은 UUID.
- 앱 시작 오류를 받는 곳이 없어, 창 없이 단일 실행 잠금만 쥔 프로세스가 남았다(다시 실행해도 아무것도 안 뜸). 이제 오류 창을 띄우고 종료한다.
- `claude -p`·git 자식 프로세스가 일찍 끝나면 stdin 쓰기 오류로 메인이 죽을 수 있었다. 분석 시간 초과는 프로세스 트리째(Windows의 cmd 감싸기 포함) 끈다.
- IPC로 온 프로젝트 설정 변경을 검증 없이 받았다(검사 명령은 매 턴 사용자 셸로 실행된다). `normalizeProjectPatch`로 알려진 필드·타입만 받는다.
- 창 위치 파일 검증, 환경 검사와 실행이 claude 경로를 다르게 판단하던 것, 닫힌 터미널의 상태가 남던 것, `install:local`이 복사 전에 기존 앱을 지우던 것과 공백 있는 경로.
- renderer: 프로젝트를 빨리 바꾸면 앞 프로젝트에서 Claude가 시작될 수 있었다. 늦게 온 변경 응답이 최신 결과를 덮었다. Claude 탭이 여럿이면 상태 바·의도 붙여넣기가 첫 탭을 봤다. 오른쪽 패널이 이전 프로젝트 내용을 잠깐 보여 줬다. 시작 중 받은 터미널 갱신을 덮어썼다. 프로젝트를 지워도 메모리에 데이터가 남았다.

**오류 로그** (ADR-0031): main에 로그가 하나도 없었고 8곳이 오류를 조용히 삼켰다. 데이터 폴더의 `logs/main.log`에 남긴다.

**규칙 집행** (`chore(lint)`): AGENTS.md에 적혀 있지만 기계가 막지 않던 규칙을 검사로 만들었다.
- ESLint: `platform/` 밖의 `process.platform`, `exec`/`execSync`, 어댑터 밖의 Claude Code 필드·플래그 이름.
- dependency-cruiser: shared는 npm 패키지 금지, preload는 Node 내장 금지, renderer는 electron 금지, main의 `lib`·`platform`과 renderer의 `lib`·`components`는 기능을 import하지 않음, 기능 밖(앱 연결 코드 등)에서도 `index.ts`만.
- 새 규칙에 걸린 기존 위반을 고쳤다: `process.platform` 7곳, Windows `.cmd` 감싸기 복사 4곳(`spawnTarget`), Claude 고유 처리 5곳(어댑터에 `replyTimeoutMs`·`stopReplyMs`·`isContinuedStop`·`blockStopReply`, 알림 이벤트에 `needsInput`, ADR-0009 덧붙임).

**구조 정리** (`refactor`)
- main: IPC를 `src/main/ipc/`(app·projects·terminal·intent + 공통 도우미)로. 결정·명세 처리 흐름은 decisions·specs 기능으로, 이벤트 수신은 `turns/hook-ingest.ts`, 작업 끝 검사 구성은 `rules/guard.ts`, 종료 확인은 `window.ts`로. Git 실행기는 `main/lib/git.ts`. 세 번 넘게 복사된 것(이벤트 생성, 기록·화면 언어, 상대 경로 붙이기, 규칙 파일 경로)을 공용 함수로. `changes-service.ts`(334줄)에서 스냅샷과 턴 diff 분리, `shared/types.ts`(474줄)를 영역별 파일로.
- renderer: 파일 행(`PathRow`), 상태 색, 불러오기(`useApi`), 권한 선택(`PermissionSelect`), 플랫폼 확인(`useIsMac`), 점선 안내(`DashedNote`)를 공용으로. 설정 창을 섹션 파일로. store(367줄)를 slice로(ADR-0032). 임의 px·색 값을 디자인 토큰으로, 터미널 색은 CSS 변수에서 읽음(ANSI 16색만 예외).
- 성능: 메모리의 이벤트를 2000개 창으로 자르고, 터미널 출력 IPC 수신기를 하나로.

**CI**: intent·guard e2e도 macOS에서 돌린다(M2~M4 경로).

**문서**: PLAN(머리말, §5 개념과 실제 타입 이름, §6 분석 인자·Stop 대기·규칙·로그, §8 완료 기준을 체크박스로, M5에 빠져 있던 할 일, §10·§12 고친 서술, §13 정한 것과 새 열린 질문, §14 구조), AGENTS(명령 표, 구조·플랫폼·UI 규칙을 집행 내용에 맞춤), README 두 개(영어판을 한국어판과 맞춤, 옛 해시 예시), ADR-0004·0009·0030 덧붙임, ADR 템플릿에 부분 상태와 덧붙임 관례, BACKGROUND의 안정 빌드 서술에 실제 운영 덧붙임, experiment-log에 결정 카드 정탐/오탐 표.

**테스트**: 단위·통합 105개 → 120개(JSON 파일, 프로젝트 설정 검증, 언어, 경로, 의도 입력, 후보 찾기, ADR 상태, 어댑터 Stop 응답). e2e 3개 통과, 바꾼 화면은 스크린샷으로 확인(라이트·다크).

## 정한 것
- ADR-0031 오류 로그, ADR-0032 store slice.
- 작업일지에 남은 이전 이력의 해시는 고치지 않고 ADR-0030 덧붙임에 대응표를 둔다(`b5f7716`→`9e6a299`, `6ec8d34`→`5fc1e11`, `45adad6`→`8b9126e`, `e08a537`→`75a997b`).
- 시작 템플릿이 대상 저장소에 AGENTS.md 등을 새로 만드는 것은 원칙 5의 예외로 PLAN에 명시(없을 때만, 사람이 미리 보고 고를 때만).

## 문제·남은 것
- 버전 태그 `v0.2.0`은 아직 달지 않았다. 태그를 달면 Releases에 설치 파일이 공개되므로 미누 확인 후.
- 실험 기준점(`docs/experiment-log.md`)이 비어 있다. hearthwild는 아직 실제 세션 전이라 지금 적으면 깨끗한 기준점이 된다.
- 하지 않은 것(PLAN M5로 옮김): 이벤트 원장 회전과 끝에서부터 읽기, 규칙 분석 작업 스레드, 타임라인 증분 계산, renderer 오류 로그, 확인 창을 앱 언어로(`window.confirm`), 파일 트리 키보드 조작, 배포 빌드 압축, Windows 실기 확인(cmd.exe가 `--json-schema` 인자를 다시 해석할 수 있는 문제 포함).
- 프로젝트 id는 Windows에서만 경로를 소문자로 바꿔 만든다. macOS의 대소문자 무시 볼륨에서 같은 폴더가 두 번 등록될 수 있지만, id를 바꾸면 기존 이벤트 원장과 연결이 끊겨 그대로 뒀다.
